# QQ ComfyUI Tools

给 ComfyUI 用的一组工具节点，覆盖多媒体加载、视频、H3 分段、Qwen 出图、深度预处理和 Lightroom 调色。

## 安装

把整个仓库放进 ComfyUI 的 `custom_nodes/QQ_ComfyUI_Tools` 然后重启 ComfyUI。

绝大多数节点只用 ComfyUI 现有的依赖。两个例外：

- `QQ-视频补帧×2` 需要额外安装 WhiteRabbit RIFE 节点，并准备 `rife47.pth`。
- `QQ-Qwen Image 2.1 AI提示词增强(PE or API)` 的「本地官方PE」需要把官方 safetensors 放进 `models/text_encoders`（或 `models/clip`）。

## 多媒体

### QQ-多媒体加载

从 ComfyUI 的 `input` 或 `output` 目录按选择顺序加载图片、音频和视频，也支持直接拖入文件。弹窗支持列表、3 列、4 列、5 列四种排列，默认 4 列；搜索按文件名过滤当前目录，结果固定 4 列；排序默认为创建时间由近及远，也可切换文件名 A-Z / Z-A、创建时间远→近、文件大小大→小 / 小→大。

输出口固定四个，互不混合：

| 输出 | 内容 |
| --- | --- |
| `multi output` | 按顺序排列的图片列表 |
| `audio output` | 音频列表 |
| `video output` | 视频列表 |
| `media_bundle` | 保留类型信息的混合媒体包 |

`external_images` 是一个可选输入，用来接入面板之外的外部图片（单张、batch 或列表输出都可以）。接上以后面板会出现「外部图片序号」行：

- 留空或填 `0`：外部图片追加到内部图片末尾
- 填单个数字 `N`：从第 N 位开始连续占位
- 填 `2,5` 这类逗号列表：逐张指定位置，数量需与接入张数一致
- 支持区间写法，例如 `2-3`

点击「提交」、按 Enter 或左键点击面板即可按占位形式预演编号。上游节点被设为「绕过」时序号框与面板里的「外部」占位块一起消失（绕过态视为没有外部图片），取消绕过即恢复，已填写的序号会保留在工作流里。

节点状态存在工作流中，重新打开后仍能复现选择结果。缩略图由后端按需生成并缓存在系统临时目录下，按源文件路径、修改时间和大小做键，源文件变化会自动重生成。

### QQ-图片包加载

适合漫画、艺术家图片包的逐张处理。支持图片与 ZIP、CBZ、TAR、TAR.GZ、TGZ、GZ（压缩的 TAR 或单张图片）；不展开嵌套压缩包。点击「选择」浏览 ComfyUI 的 input/output，或点击「上传」/拖入本地文件。压缩包以抓牌（折扇）式卡牌显示，只占一个格子：图片统一裁切为 3:4，正面完整显示首图，背后依次叠第 2、3 张图并旋转展开，各露出约 1/4；不足 3 张时自动减少叠层。包内图片按完整相对路径自然排序（`page2` 在 `page10` 前）；多个来源按面板排列顺序处理，可拖动或用上下箭头调整。

将「图像」接到处理链，并连接保存/预览等输出节点。默认从第 1 张开始，每次输出一张；开启「自动下一张」后，**整个工作流成功完成**才自动排队处理下一张，默认跑完停止。浏览器需要保持连接；报错、取消、切换工作流、手动更改序号或已有其他排队任务时停止自动推进。一次只自动排一项任务，建议队列批次数保持 1，并关闭 ComfyUI 自带的自动排队。一个工作流若使用多个此加载器，会一起推进，任意加载器到末张时整组停止。

「停止自动」关闭自动排队，已在执行的任务会继续完成；「回到首张」重置序号后可手动点击运行。修改来源顺序会重置为第 1 张。每张图都重新执行加载，单张图片重复执行也不会被缓存跳过。

可选 `file_path` 接收绝对文件路径或 input 相对路径，`output::子目录/文件名` 表示 output 文件；支持换行/逗号/分号分隔多个路径，非空路径优先于面板。输出为「图像」「当前序号」「总张数」「图包信息」；「图包信息」记录当前来源、原始压缩格式和包内相对路径，供专用保存节点使用。GZ 首次索引会解压到 ComfyUI 临时目录，之后逐张读取缓存，不重复解压整个包。


### QQ-图片包保存

连接 `QQ-图片包加载` 的「图像」和「图包信息」。节点会按来源自动选择输出格式：ZIP 保存为 ZIP、CBZ 保存为 CBZ、TAR/TAR.GZ/TGZ 保存为对应 TAR 格式；单张图片和单张 GZ 图片也按原格式保存。

多个图包会分别生成对应的输出文件，例如 `package_edited.cbz` 与 `book_edited.tar.gz`。每次执行只替换当前序号对应的包内图片，其余成员保持不变；开启加载器的「自动下一张」后，保存节点会在同一输出包中逐步累积处理结果。默认输出到 output/qq_image_packages，可修改「输出目录」与「输出后缀」；来源文件不会被修改。

### QQ-媒体序号输出

接 `multi output` 或 `media_bundle`，按当前媒体数量自动生成独立输出端：`multi output` 依次输出图片，`media_bundle` 按图片、音频、视频分组依次输出，端口名带序号。

最多支持 64 个输出；未连接的尾部端口自动收缩，已接线的端口会保留以避免断线。节点内置与 `ImageScaleByAspectRatio V2` 一致的缩放规则，默认关闭，只作用于图片输出，同一 media_bundle 里的音频和视频不受影响。

### QQ-自动拆分媒体

自动识别输入中的图像、音频和视频，输出图像列表、音频列表、视频列表，以及一张拼合图。

输入可接 `media_bundle` 或单独的 `IMAGE`；同时连接时优先使用 `media_bundle`。`图片组合` 会保留每张图的原始宽高比，按自动网格拼接，图片之间固定 10px 黑色分隔，单张长边默认限制为 1024（`组合图片长边` 可调）。`组合排列` 提供从左向右、从右向左、单元居中排列三种。空媒体类别会被 ComfyUI 惰性阻塞，不影响其它已连接类别。

## 工作流控制

### QQ-绕过规则

用文字或正则匹配**节点标题**或**组名**，把命中的节点设为 Bypass。节点框匹配单个节点，组框匹配组名（组内全部节点都会被绕过）；两个框都填时结果相加，多条规则用逗号分隔。

- 普通文字按**包含**匹配；含 `^ $ * . + ? ( ) [ ] { } |` 等符号时按正则匹配
- 规则前加 `!` 表示排除，优先级高于命中
- 关闭「启用」后，之前被绕过的节点会恢复原状态

示例：节点框 `^Get_图片, !Get_图片 1` 会绕过所有 `Get_图片` 开头的节点，但保留 `Get_图片 1`。

### QQ-绕过规则开关

`QQ-绕过规则` 的伙伴开关，只控制当前画布中的规则节点，不建立执行连线。首次按画布中的规则节点顺序建立绑定，之后按节点 ID 保持绑定，名称仅用于自定义显示。

### QQ-魔术贴

放进某个组里使用。模式选「绕过」时，所在组内除魔术贴以外的所有节点都会被标记为 Bypass；选「启用」时恢复它们被标记前的状态。

魔术贴自己不受任何绕过控制（包括 `QQ-绕过规则` 和组内其它魔术贴）。恢复只作用于被标记过的节点，你手动绕过的节点保持原样。嵌套组时只作用于魔术贴所在的最内层组。

### QQ-获取点

按名称读取 KJ 设置点（`SetNode`）的值，和 KJ 获取点同机制，但多一个 `启用` / `绕过` 开关：选绕过时消费者视为未连接（例如一键出图的 `latent_image` 回退到图1分辨率）。

界面上它是虚拟节点：排队时前端把它编译成真实连线，本身不进 prompt。所以直接走 API 提交包含它的 prompt 会报错，请在界面里使用。

### QQ-多值设置 / QQ-多值输入

`QQ-多值设置` 收集多个动态类型的值，供 KJ 获取节点按名称读取。`QQ-多值输入` 是前端虚拟节点，提供多个控件值的动态输入，不会单独执行。

### QQ-潜空间切换 / QQ-长宽交换

`QQ-潜空间切换` 在多个 LATENT 之间切换，下拉选项是输入接口的名称。连上最后一个空接口会自动再增加一个接口，断开空接口会自动收回。

`QQ-长宽交换` 按开关决定是否交换宽度和高度。

### 轮询切换与文本

- `QQ-图像轮询切换` 按 `input1` → `input8` 顺序输出第一个有内容的图像，只扫描一趟。默认只显示 2 个输入口，接满自动增加，最多 8 个。适合「优先用 A，A 没有就用 B」。
- `QQ-文本轮询切换` 是它的文本版本。与图像版不同，**空字符串和纯空白算「没有内容」**。适合「优先用增强后的提示词，增强节点被绕过时回退到原始提示词」。
- `QQ-多行文本` 把系统提示词、分隔符和自由文本以空行连接；首行开关可隐藏系统提示词框，隐藏不影响输出，全部内容随工作流保存。
- `QQ-文本合并` 用分隔符拼接两段文本。分隔符支持转义：`\n` 换行、`\r` 回车、`\t` 制表符、`\\` 反斜杠。两个输入口可选，只接一段时原样输出，不会多出分隔符。

## 视频

### QQ-视频开头黑屏

将视频开头指定秒数（默认 0.05）替换为纯黑帧，同时保留原 FPS、音频、元数据、分辨率和位深。

### QQ-视频补帧×2

用已安装的 WhiteRabbit RIFE 4.7 分块补帧，把帧率加倍，保持分辨率、音频和时长。

`memory_mode` 默认「低内存（FP16）」，只降低结果缓存精度，RIFE 推理仍用 FP32；补帧后还要做精度敏感处理时可选「最高兼容（FP32）」。`chunk_frames` 默认 96，调小会降低临时内存，调大通常减少分块调用开销。

### QQ-保存视频

保存视频，并输出每秒第一帧、视频最后一帧和手动指定的关键帧。

自定义帧用从 0 开始的帧索引，逗号分隔，例如 `0,24,48,120`；空输入不额外输出帧。`time_format` 可选择仅用递增序号，或加入本机时间：`年月日-时分（冲突自动编号）` 会先生成 `Wsl_20260102-1730.mp4`，同一分钟保存多个视频时才依次追加 `-2`、`-3`。

## H3 分段工作流

`QQ/H3` 下的节点与 `ComfyUI-MiniMaxH3-Easy` 的分段工作流配合；其他分类的节点独立使用，不依赖该仓库。

### QQ-H3分段时长

把 `6,6`、逐行 `6秒`、中文标点、括号和常见分段标注统一转换为源版上下文分段节点可接受的逗号格式。

输出四个值：`分段秒数`、`总秒数`、`分段FPS`、`目标总帧数`。FPS 是播放速率，不会按分段相加；目标总帧数按合计时长一次应用 `17k+5` 原生时间网格计算。

需要注意：`上下文帧数`（默认 22）是分段之间用于连续性的重叠帧数，不属于时长，仍应在源版上下文分段节点中单独设置。使用 `6,6` 时提示词也必须有两个 `---` 分隔的内容块，否则源版节点会报「分段数量不匹配」。

### QQ-H3提示词

独立提示词输入节点，可连接到 MiniMax H3 Easy。结构化编辑模式支持用 `@` 选择目标 H3 节点中的媒体资源，`@Picture 1`、`@Image 1`、`@图片 1` 等写法都能识别，并转换为源 H3 节点使用的运行时占位符。

### QQ-H3功能区路由

只执行当前选中的功能区，未选中的输入使用惰性连接。

### QQ-H3 分段彩噪

接在一采和二采之间：

```text
MiniMax H3 Easy Segment Render.segments
  -> QQ-H3 分段彩噪.segments
  -> MiniMax H3 Easy Segment Refine.segments
```

逐段解码一采结果，只给实际交付画面加入块状彩噪，再编码回原来的 `MINIMAX_H3_SEGMENTS` 结构；首部上下文、音频、提示词、媒体引用和分段计划保持不变。默认强度从 `0.20` 在末尾 8 帧渐退到 `0.00`。

节点会增加一次视频 VAE 解码与编码，属于实验性二采预处理。

## 深度估计预处理

`QQ-照度均衡` 与 `QQ-深度融合` 用来在普通图片转深度图之前做照度处理。低频光照梯度常被深度模型误当成几何，Depth Pro 这类度量深度模型还会用整幅图的统计预测焦距，所以这里只压光照梯度、不动细节层。

### QQ-照度均衡

在线性光空间用多尺度低通估计低频照度，保留全局中位亮度，并对修正幅度做软限幅以避免光晕。按 `档位强度` 输出多档变体，默认 `0,50,100`，其中 0 档就是原图。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `档位强度` | `0,50,100` | 逗号分隔的 0-100 强度，最多 9 档 |
| `暗部细节` | 0 | 仅提升暗部低对比区域的结构 |
| `最大修正幅度` | 1.0 | 单位 EV 的软限幅，防光晕 |
| `滤波半径` | 0 | 0 表示按短边自动计算 |
| `全局曝光归一` | 关 | 需要统一整批亮度时打开 |

输出 `图像` 和一个 `档位数`。

### QQ-深度融合

把多路深度按 `每图档位数` 分组融合，默认做尺度归一后的中值融合，额外输出一张一致性图：越白表示各档结果越一致，越黑表示该图对照度处理越敏感，建议人工复核。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `每图档位数` | 3 | 接 QQ-照度均衡 的档位数输出 |
| `融合方式` | 中值 | 还可选均值、截尾均值 |
| `尺度归一` | 开 | 先归一尺度再融合 |
| `一致性增益` | 3.0 | 一致性图的灵敏度 |

标准接法：

```text
图像 -> QQ-照度均衡 -> Depth Pro -> QQ-深度融合 -> 融合深度
                       ^ 每图档位数接 QQ-照度均衡 的档位数输出
```

Depth Pro 的 `metric_depth` 是三通道批次，可直接接入。1536×1536 输入下单张三档处理约 0.4 秒，融合约 0.2 秒。

## 图像生成

### QQ-Qwen Image 2.1 AI提示词增强(PE or API)

复刻 TE MAN 的 Qwen Image 2.1 提示词增强，去掉旧的「本地」通用 LLaMA 通路，保留「本地官方PE」和「API」两种方式。

- 首行 `启用` 是总开关：关闭时不调用任何模型，`输入提示词` 原样从 `增强提示词` 口输出。
- `任务模式` 支持 自动 / 文生图 / 图生图，自动模式按是否接入参考图选择。
- `参考图` 是单个列表输入口，顺序即 `<image1>`…`<imageN>`，最多 9 张，超出直接报错。接 `QQ-多媒体加载` 的 `multi output` 时按列表顺序编号，与加载器面板序号一致。
- 本地官方PE 只读取 `models/text_encoders`（或 `models/clip`）里的单文件 safetensors，经 ComfyUI 自带文本编码器栈加载。
- API 走 OpenAI 兼容接口，参考图按最长边压成 JPEG 后 base64 发送。`api_url` / `api_key` 留空时会回读本机 TE MAN 插件的 `config.ini`。
- `最大生成token` 默认 4096，`最大边长` 默认 1024。

### QQ-Qwen Image 2.1 一键出图(编码+K采样+VAE解码)

把 Qwen Image 2.1 编码、KSampler 和 VAE 解码合成一个节点：内部先按官方规则编码正负条件和参考图 latent，再跑采样，最后解码直接输出 `图像`。

采样控件与官方 KSampler 一致（seed / steps / cfg / sampler_name / scheduler / denoise）。`参考图` 是单个列表口，最多 16 张。可选的 `latent_image` 口接自定义空 latent（如 `EmptyLatentImage`）来指定输出宽高比和分辨率；不接时采样画布跟随第一张参考图缩放后的尺寸。需要单独控制采样环节时，改用原生节点组合。

### QQ-Grok图像生成

调用已配置的 OpenAI 兼容 Grok2API 生成或编辑图片，默认模型 `grok-imagine-image-2.0`，输出标准 `IMAGE`。

配置方式：复制 `config/grok_image_endpoints.example.json` 为 `<ComfyUI>/user/QQ_ComfyUI_Tools/grok_image_endpoints.json`，也可以用环境变量 `QQ_GROK_IMAGE_CONFIG` 指定路径。每组至少填写 `name`、`endpoint`、`api_key`，可选 `edits_endpoint`、`model`、`allow_nsfw`。

节点只显示配置名称，不会在工作流中保存 endpoint 或 API Key。图片比例和分辨率由服务端生成结果决定，节点不会在本地拉伸或裁剪返回图片。

## Lightroom 调色

六个节点都是可串联的调色环节，控件默认全为 0，滑条以渐变提示左右效果。除 `颗粒效果` 外都同时支持图像和视频。

| 节点 | 对应 Lightroom 面板 |
| --- | --- |
| `QQ-LR-光线调节` | 曝光、对比度、高光、阴影、白色、黑色 |
| `QQ-LR-色彩调节` | 色温、色调、鲜艳度、饱和度 |
| `QQ-LR-基础增强` | 纹理、清晰度、去朦胧 |
| `QQ-LR-暖色调色` | 红、橙、黄、绿四色区 HSL |
| `QQ-LR-冷色调色` | 青、蓝、紫、洋红四色区 HSL |
| `QQ-LR-颗粒效果` | Effects → Grain |

`颗粒效果` 默认值为数量 0、大小 25、粗糙度 50，另有随机种子保证同一工作流重复执行得到相同颗粒。算法在亮度维度叠加并保留 alpha 通道，建议接在其它调色节点之后。

## 兼容性

- 旧工作流里的 `Wysl...` 节点类型不会自动转换成 `QQ...`，需要手动替换。
- 已删除的 `QQ-LightroomImage` / `QQ-LightroomVideo` 请改用分项调色节点串联。
- 视频节点通过 `core/video_api.py` 兼容不同 ComfyUI 版本的 VIDEO API。
